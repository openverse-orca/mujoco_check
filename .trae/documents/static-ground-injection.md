# 本地静态地面注入

## Context

需要在现有模型上注入地面等本地元素，同时继续与 OrcaLab 交换 `qpos/qvel/qacc`。首版提供固定参数的静态地面注入/移除按钮，地面可参与本地主仿真的碰撞；不改写远端模型，远端视口也不会新增该地面。注入只增加无自由度元素，确保原有 Joint 的状态维度和顺序完全不变。

## 实现方案

### 1. 静态 XML 注入与兼容性校验

新增 `model_injection.py`：

- 提供地面片段和追加函数，将静态 `plane Geom` 添加到 `worldbody` 末尾。
- XML 解析后拒绝片段中的 `joint/freejoint`；后续可复用同一函数扩展其他静态 `geom/body`。
- 始终从未注入的基线 XML 生成结果，避免重复添加。
- 记录并比较注入前后的 `nq/nv/nu/njnt`、`jnt_type`、`jnt_qposadr`、`jnt_dofadr` 和 Joint 名称；任一变化都拒绝提交。

### 2. 复用事务式模型替换

调整 `main.py` 的 `Viewer.load_xml()`，将候选模型构建与提交拆成可复用流程：

- 保留 `xml_path` 和 `xml_text` 为原始来源路径、未注入文本；新增当前生效 XML 文本及 `ground_injected` 状态。
- 注入时将派生 XML 写到原 XML 同目录的临时文件，再用 `MjModel.from_xml_path()` 编译，保证 include、mesh、texture 等相对路径不变；编译后删除临时文件。
- 候选 Model/Data、布局校验、ModelIndex、Scene、MjrContext 全部成功后才替换当前模型；失败保留旧模型、模式和注入状态，并通过现有状态栏报错。
- 成功注入或移除后停止 sync/push、清除外力、恢复初始状态并回到 `view`，复用现有 `rebind_model()` 和相机重置逻辑。
- XML 源码页展示实际生效的派生文本，原始基线文本单独保留。
- 新打开或重新拉取模型时默认不注入，由用户主动开启。

### 3. 保留 OrcaLab 下载资源

当前远端模型加载后会立即删除下载目录，导致之后无法重新编译。调整为：

- 远端加载成功后由 Viewer 接管该资源目录，供后续注入/移除重新编译。
- 加载新模型成功或程序退出时清理旧目录；失败、过期请求仍立即清理各自的新目录。
- 注入/移除复用当前目录，不重复清理。

现有远端拉取仍写入 `qpos/qvel/qacc`，本地推送仍只发送 `qpos,time`；布局校验保证这些数组与原远端 Joint 一一对应。地面只改变本地主仿真的接触环境，不同步接触、约束或地面模型到远端。

### 4. 简单 UI

在 `inspector_ui.py` 的“模型来源”区域添加一个按钮：

- 未注入时显示“注入本地地面”，已注入时显示“移除本地地面”。
- 未加载 XML 或正在拉取时禁用。
- 使用现有回调绑定方式调用 `Viewer.set_ground_enabled()`，只有成功提交后才更新按钮状态。
- 按钮下方用一行说明“仅影响本地模型和仿真，不写入 OrcaLab”。

### 5. 打包

在 `pyproject.toml` 的 `py-modules` 中加入 `model_injection`，确保 `uv run mtool` 和工具安装均包含新模块。

## 验证

- 为 XML 注入、幂等性、静态限制和 Joint 布局校验添加单元测试。
- 验证带相对 include/资源的 XML 在注入和移除后均可编译。
- 验证四种 Joint 的 `qpos0`、地址和顺序不变，原远端快照仍可应用，本地推送数组保持原形状。
- 验证自由 Body 在本地主仿真中能够与地面碰撞。
- 验证成功注入/移除回到 `view` 且恢复初始状态；非法注入或编译失败不影响旧模型和当前模式。
- 验证 OrcaLab 资源目录在重新编译前有效，并在模型替换和退出时正确清理。
- 执行完整 `unittest` 和 `git diff --check`，再实际检查本地 XML 与 OrcaLab 两种来源的注入按钮、显示和状态同步。
